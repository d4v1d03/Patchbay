What it does

A sandbox, a loop, and checks on both ends

Dedicated sandbox

Each session gets its own container with your repo cloned in: non-root, every Linux capability dropped, CPU, memory and process limits. Nothing runs on your machine.

Tested before it's done

It runs the tests after each change and only finishes once they pass. The summary names the command it ran and what came back.

Second-opinion review

Optionally, a separate model call reads the diff and the test output before a run is accepted, and sends the work back with specific issues.

Every step visible

Commands and their output stream to your browser as they run. Open any step to see the exact prompt the model was given.

Cache-aware context

A fixed prompt prefix lets the provider cache most of each request, so a long session costs a fraction of its raw token count. Old tool output can be trimmed when a session runs long.

Picks up where it left off

Follow-ups continue in the same sandbox with the whole conversation. If a worker dies mid-run, the run resumes from its saved transcript.

How it works

From a sentence to a patch

  1. 01

    Describe

    Write the task in plain English and, if you like, point it at a public GitHub repo.

  2. 02

    Sandbox

    A fresh container starts and the repo is cloned into it.

  3. 03

    Work

    The agent reads, edits and runs the tests, fixing what fails, while you watch.

  4. 04

    Take it

    Review the diff, then download it as a patch or the whole project as a zip.
